CS7 Algorithm Design and Problem Solving — Cambridge IGCSE Computer Science Study Guide

7.1 Program Development Life Cycle

The program development life cycle is a structured, organised plan used when creating a new computer program. There are several varieties of life cycle models, including cyclic, spiral, waterfall, and rapid development. All models include the following four stages:

  1. Analysis — The problem is explored, requirements are identified, and the problem is decomposed into subproblems.
  2. Design — Algorithms are planned using structure diagrams, flowcharts, and pseudocode.
  3. Coding — The program is written in a chosen programming language, with iterative testing during development.
  4. Testing — The finished program is tested to ensure it fully works, does not crash, and meets all requirements.

7.2 Analysis and Decomposition

Decomposition is used to split a problem into smaller subproblems during the analysis stage. Each subproblem can then be tackled separately and implemented as a subprogram. This makes complex problems more manageable and allows different team members to work on different parts.

Key steps in analysis:

  • Explore the problem and identify requirements
  • Use decomposition to break the problem into component parts
  • Identify inputs, processes, and outputs for each subproblem

7.3 Design — Structure Diagrams

A structure diagram is developed by decomposing a program into its subprograms. The diagram has the name of the program at the top, and below it are its subprograms. Each subprogram can be split down further as needed.

How to create a structure diagram:

  1. Place the program name at the top
  2. Identify the main subprograms (e.g. Input, Process, Output)
  3. Break each subprogram into smaller components
  4. Continue decomposing until each box represents a single, programmable task

Example — Calculator:

  • Top level: Calculator
  • Second level: Input, Process, Output
  • Input breaks into: Input number1, Input symbol, Input number2
  • Process: number1 symbol number2
  • Output: Output answer

Example — Chess Game:

  • Top level: Chess
  • Second level: New players, New game, Make move, Check won
  • Each breaks down further into specific tasks (e.g., Make move → Output player's turn, Input piece, Input move, Check move valid, Move piece)

7.4 Pseudocode

Pseudocode is any code that is not written on a computer to run. It uses keywords and constructs such as IF statements, WHILE loops, FOR loops, INPUT, and OUTPUT. It is a readable, code-like representation that all programmers can understand and translate into any programming language.

Key rules for valid pseudocode:

  • Use programming constructs (IF, WHILE, FOR, INPUT, OUTPUT)
  • Split the program into clear, translatable steps
  • Use assignment operators (← or =)
  • Avoid natural language descriptions that cannot be directly coded

Valid pseudocode example:

`

INPUT Number1

IF Number1 < 10 THEN

OUTPUT "too small"

ELSE

OUTPUT "valid"

ENDIF

`

Invalid pseudocode uses natural language like "Input the value X" or "Loop 10 times" — these cannot be directly converted to code.

7.5 Coding

Once you have decomposed your problem and designed algorithms using flowcharts and/or pseudocode, you can start writing the program in your chosen programming language. This stage includes iterative testing — testing each subprogram with a range of data before moving on to the next step.

7.6 Testing and Test Data

When you have finished your program, you need to carry out testing to make sure it fully works, does not crash, and meets all requirements. There are four types of test data:

  1. Normal data — Data that the program should accept (within valid range)
  2. Abnormal data — Data that the program should not accept (outside valid range, wrong type)
  3. Extreme data — Data at the edge of what is allowed (boundary values that should be accepted)
  4. Boundary data — Data on the edge of being accepted and being rejected (tests both sides of a limit)

Example — Age input between 10 and 100:

  • Normal: 10, 20, 50, 100
  • Abnormal: 9, −1, 101, 200, "age", "30", 12.2
  • Extreme: 100 (largest accepted), 10 (smallest accepted)
  • Boundary: 100 and 101 (upper), 9 and 10 (lower)

7.7 Common Algorithms

Search Algorithms

A search algorithm checks a set of data to identify whether a specific value exists in the data. One example is a linear search.

Linear Search

A linear search checks each item one at a time, starting from the first item and continuing until it either finds the item or reaches the end of the data.

Algorithm (basic version using FOR loop):

`

FOR ArrayIndex = 0 to LENGTH(Array) - 1

IF DataArray[ArrayIndex] = SearchValue THEN

OUTPUT "Found at " & ArrayIndex

ENDIF

NEXT ArrayIndex

`

Efficient version (stops when found using WHILE loop):

`

Found ← FALSE

ArrayIndex ← 0

WHILE Found = FALSE AND ArrayIndex < LENGTH(Array) DO

IF DataArray[ArrayIndex] = SearchValue THEN

OUTPUT "Found at " & ArrayIndex

Found ← TRUE

ELSE

ArrayIndex ← ArrayIndex + 1

ENDIF

ENDWHILE

`

Sorting Algorithms — Bubble Sort

A bubble sort compares adjacent pairs of items and swaps them if they are in the wrong order. It passes through the entire list repeatedly until the data is sorted.

Two stopping conditions:

  1. The algorithm has been through the list (length − 1) times
  2. The algorithm has passed through the list without making any changes

Version 1 — Fixed number of passes:

`

FOR NumberPasses ← 0 to LENGTH(DataArray) - 1

FOR Index ← 0 to LENGTH(DataArray) - 1

IF DataArray[Index] > DataArray[Index + 1] THEN

Temp ← DataArray[Index]

DataArray[Index] ← DataArray[Index + 1]

DataArray[Index + 1] ← Temp

ENDIF

NEXT Index

NEXT NumberPasses

`

Version 2 — Stops when no changes (more efficient):

`

NumberPasses ← 0

WHILE Changes = FALSE OR NumberPasses <= LENGTH(DataArray) - 1 DO

Changes ← FALSE

FOR Index ← 0 to LENGTH(DataArray) - 1

IF DataArray[Index] > DataArray[Index + 1] THEN

Temp ← DataArray[Index]

DataArray[Index] ← DataArray[Index + 1]

DataArray[Index + 1] ← Temp

Changes ← TRUE

ENDIF

NEXT Index

ENDWHILE

`

To sort in descending order, change the comparison from > to <.

7.8 Totalling, Counting, Maximum, Minimum, and Average

Totalling

Totalling is adding a group of values together to give a total.

Steps:

  1. Initialise a variable to store the total: Total ← 0
  2. Add each value to the running total: Total ← Total + Value

`

Total ← 0

FOR X ← 0 TO 9

Total ← Total + INPUT("Enter a value")

NEXT X

OUTPUT Total

`

Counting

Counting is working out how many of something there are.

Steps:

  1. Initialise a counter variable: Count ← 0
  2. Add 1 to the counter each time: Count ← Count + 1

`

Count ← 0

Number ← 0

WHILE Number <> -1 DO

Number ← INPUT("Enter a number. Enter -1 to stop")

Count ← Count + 1

ENDWHILE

`

Finding the Minimum

The minimum value is the smallest value within a set.

Steps:

  1. Initialise the minimum to a large value: Minimum ← 9999
  2. Compare each value: IF Number < Minimum THEN Minimum ← Number

`

Minimum ← 9999

Number ← 1

WHILE Number >= 1 DO

Number ← INPUT("Enter a number or 0 to stop")

IF Number < Minimum THEN

Minimum ← Number

ENDIF

ENDWHILE

`

Finding the Maximum

The maximum value is the largest value within a set.

Steps:

  1. Initialise the maximum to a small value: Maximum ← -9999
  2. Compare each value: IF Number > Maximum THEN Maximum ← Number

`

Maximum ← -9999

Number ← 1

WHILE Number >= 1 DO

Number ← INPUT("Enter a number or 0 to stop")

IF Number > Maximum THEN

Maximum ← Number

ENDIF

ENDWHILE

`

Finding the Average

The average (mean) is the total of all values divided by the count of values.

Formula: Average = Total / Count

`

Count ← 0

Total ← 0

Number ← 1

WHILE Number >= 1 DO

Number ← INPUT("Enter a number or 0 to stop")

Total ← Total + Number

Count ← Count + 1

ENDWHILE

Average ← Total / Count

`

7.9 Validation on Input

Validation is the checking of data that is input to make sure it is reasonable, and/or within set bounds.

Range Check

A range check assesses whether data is within one or two bounds (e.g., age must be between 0 and 100).

`

Number ← INPUT("Enter a number between 1 and 10")

WHILE Number < 1 OR Number > 10 DO

OUTPUT("Invalid please try again")

Number ← INPUT()

ENDWHILE

`

Length Check

A length check checks the number of characters in a string.

`

Data ← Input()

WHILE LENGTH(Data) < 10 DO

OUTPUT("Invalid, please try again")

Data ← INPUT()

ENDWHILE

`

Type Check

A type check verifies that data is of the correct data type (integer, real, string, Boolean).

Methods:

  1. Use .GetDataType() to return the data type and compare
  2. Use .IsInteger() or .IsString to return True/False

`

INPUT Data

IF Data.GetDataType() <> Integer THEN

OUTPUT ("Invalid")

ENDIF

`

Presence Check

A presence check ensures that some data has been entered (not null or empty string).

`

INPUT Data

WHILE Data = "" DO

OUTPUT("Invalid please try again")

INPUT Data

ENDWHILE

`

Format Check

A format check ensures data is entered in a specific format (e.g., date as DD/MM/YYYY, ID as 1 number followed by 2 characters).

Uses SUBSTRING(String, X, Y) to extract and check individual characters at specific positions.

Check Digit

A check digit is calculated from a set of numbers and is input with the numbers. When data is entered, the calculation is performed again and compared with the final number to detect data entry errors.

7.10 Verification of Data

Verification is a check that you have copied data accurately from the original source. It ensures the data entered matches what was originally written.

Two forms of verification:

  1. Visual check — Compare the data entered to the original (e.g., reading from a paper copy and checking it on screen)
  2. Double entry check — The same data is entered twice (usually by different people), then the computer checks for differences

Important distinction: Validation checks if data is reasonable; verification checks if data has been copied accurately. Verification only confirms accurate copying — the original data may still be incorrect.

7.11 Trace Tables

A trace table is a structure to help you follow an algorithm manually, to find errors or work out what the algorithm does.

How to create a trace table:

  1. Identify all variables in the algorithm — each gets its own column
  2. Add an OUTPUT column if the program outputs data or strings
  3. Read through the algorithm one line at a time
  4. Write new values in the table as they change
  5. When a variable gets a new value, write it below the previous value in the same column

Key rules:

  • Follow code line by line — do not jump ahead
  • When you reach the end of a loop, go back to the loop condition
  • Outputs must match exactly what is in the code
  • Specific inputs can be given to test different parts of the algorithm

Trace Table with Selection

For IF/ELSE statements, evaluate the condition with current variable values and follow the appropriate branch.

Trace Table with Loops

For loops (WHILE/FOR), repeat the body until the condition becomes false, updating variables each iteration.

7.12 Finding the Purpose of an Algorithm

A trace table can help you work out the purpose of an algorithm by following it step-by-step to see what happens to the values, what changes are made, and when.

Steps to describe an algorithm's purpose:

  1. Run the algorithm with test data using a trace table
  2. Identify what each section of code does (not just repeat what the code says)
  3. Look at the overall pattern of inputs, processes, and outputs
  4. Write a description that explains the algorithm's purpose in English

Important: When describing an algorithm, do more than repeat the line of code. Explain what the algorithm achieves, not just how it works line by line.

7.13 Finding and Correcting Errors

To find errors in an algorithm:

  1. Know the purpose of the algorithm (what it should do)
  2. Test with different data, completing trace tables if needed
  3. Compare what the algorithm actually does vs. what it should do
  4. Identify the specific errors and make corrections

Common errors to look for:

  • Variables initialised to wrong values (e.g., Total ← 1 instead of Total ← 0)
  • Overwriting instead of accumulating (e.g., Total ← Number instead of Total ← Total + Number)
  • Off-by-one errors in loop conditions (e.g., WHILE Quantity < 5 runs 4 times, not 5)
  • Wrong comparison operators (< instead of >)
  • Wrong variable identifiers (e.g., using Large instead of Largest)

Methods for finding errors:

  1. Trace tables — Follow the algorithm step by step and compare output to expected result
  2. Reading the code — Check each requirement against the algorithm to see if it is met
  3. IDE debugging tools — Use breakpoints and variable inspection in an Integrated Development Environment

Flowcharts

Flowcharts are graphical representations of algorithms using standard symbols:

  • Oval/Rounded rectangle — Start/End (Terminator)
  • Parallelogram — Input/Output
  • Rectangle — Process
  • Diamond — Decision (Yes/No)
  • Arrows — Flow of control

Flowcharts can be converted to pseudocode and vice versa.

Practice Questions

Question CS7.01

What are the four stages of the program development life cycle?

Answer: The four stages are: (1) Analysis — the problem is explored and requirements identified; (2) Design — algorithms are planned using structure diagrams, flowcharts, and pseudocode; (3) Coding — the program is written in a programming language; (4) Testing — the program is tested to ensure it works correctly and meets requirements.

Question CS7.02

Define the term 'decomposition' and explain why it is used in the analysis stage.

Answer: Decomposition is the process of splitting a problem or system into smaller subproblems or sub-systems. It is used in the analysis stage because it allows developers to identify the requirements for each component part separately, making complex problems more manageable. Each subproblem can then be implemented as a subprogram.

Question CS7.03

Describe the purpose of pseudocode and give one rule for writing valid pseudocode.

Answer: Pseudocode is used to plan algorithms in a readable, code-like format that all programmers can understand and translate into any programming language. A rule for valid pseudocode is that it must use programming constructs such as IF, WHILE, FOR, INPUT, and OUTPUT — it should not be written in plain natural language that cannot be directly converted to code.

Question CS7.04

Identify four different types of test data and give an example of each for a program that accepts numbers between 1 and 50.

Answer: (1) Normal data: any number between 1 and 50 (e.g., 25); (2) Abnormal data: data outside the range or wrong type (e.g., 0, 51, "hello"); (3) Extreme data: data at the very edge of the valid range (e.g., 1 and 50); (4) Boundary data: data on both sides of the limits (e.g., 0 and 1 at the lower bound, 50 and 51 at the upper bound).

Question CS7.05

Explain how a linear search algorithm works.

Answer: A linear search checks each item in a set of data one at a time, starting from the first item. It compares each item with the search value. If the item matches, the search is complete and the position is reported. If the item does not match, the algorithm moves to the next item. The search continues until the item is found or all items have been checked without finding a match.

Question CS7.06

Describe how a bubble sort works and state the two conditions for stopping.

Answer: A bubble sort compares the first two adjacent values; if they are in the wrong order, it swaps them. It then moves to the next pair (values 2 and 3) and repeats. This continues until the end of the list, completing one pass. The algorithm stops when either: (1) it has completed (length − 1) passes through the list, or (2) it has completed a full pass without making any swaps, meaning the data is already sorted.

Question CS7.07

Explain the difference between the two versions of the bubble sort algorithm in terms of efficiency.

Answer: Version 1 always runs (length − 1) passes regardless of whether the data is already sorted, making it less efficient. Version 2 uses a flag variable to track whether any swaps were made during a pass; if no swaps occur, the algorithm stops early because the data is already in order. Version 2 is more efficient because it avoids unnecessary passes through already-sorted data.

Question CS7.08

Write a pseudocode algorithm to find the total and average of 10 numbers input by a user.

Answer:

`

Total ← 0

FOR X ← 0 TO 9

Number ← INPUT("Enter a number")

Total ← Total + Number

NEXT X

Average ← Total / 10

OUTPUT "Total: ", Total

OUTPUT "Average: ", Average

`

Question CS7.09

Explain the difference between totalling and counting.

Answer: Totalling is adding a group of values together to get a sum (e.g., Total ← Total + Value). Counting is tracking how many items there are by incrementing a counter by 1 each time (e.g., Count ← Count + 1). Totalling accumulates the actual values, while counting simply tracks the number of occurrences.

Question CS7.10

Describe how you would find the minimum value from a set of numbers using an algorithm.

Answer: To find the minimum: (1) Initialise a minimum variable to a very large value (e.g., Minimum ← 9999). (2) Compare each input number to the current minimum. (3) If the number is smaller than the current minimum, replace the minimum with that number (Minimum ← Number). (4) After all numbers have been checked, the minimum variable holds the smallest value.

Question CS7.11

What is validation? Give three examples of validation checks.

Answer: Validation is the checking of data that is input to make sure it is reasonable and within set bounds. Three examples are: (1) Range check — ensures data is within specified bounds (e.g., age between 0 and 100); (2) Length check — ensures a string has the required number of characters (e.g., password at least 8 characters); (3) Type check — ensures data is the correct data type (e.g., checking input is an integer, not a string).

Question CS7.12

Explain the difference between validation and verification.

Answer: Validation checks that data input is reasonable and within set bounds (e.g., an age must be between 0 and 100). Verification checks that data has been copied accurately from the original source (e.g., matching a typed entry to a paper form). Validation ensures data is sensible; verification ensures data has been entered correctly. However, verification only confirms accurate copying — the original data may still be incorrect.

Question CS7.13

Describe the two types of verification checks.

Answer: (1) Visual check — the user compares the data entered on screen to the original source (e.g., reading each line from a paper copy and checking it matches what is on the computer). (2) Double entry check — the same data is entered twice, usually by different people, and the computer checks whether there are any differences between the two entries.

Question CS7.14

What is a trace table and what is it used for?

Answer: A trace table is a structure used to follow an algorithm manually by recording the values of each variable at each step of execution. It is used to: (1) dry run an algorithm to see what it does with specific input data; (2) find the purpose of an unknown algorithm; and (3) find errors in an algorithm by comparing the actual output to the expected output.

Question CS7.15

Describe the steps for creating a trace table from an algorithm.

Answer: (1) Identify all variables in the algorithm — each gets its own column. (2) Add an OUTPUT column if the program produces output. (3) Read through the algorithm one line at a time, starting from the first line. (4) When a variable's value changes, write the new value below the previous value in that variable's column. (5) For loops, go back to the loop condition when reaching the end of the loop body. (6) Record outputs exactly as they appear in the code.

Question CS7.16

Perform a linear search for the number 6 in the following data: 10 5 6 8 1 2. Show each comparison.

Answer: Compare 10 with 6 — not the same. Compare 5 with 6 — not the same. Compare 6 with 6 — they are the same. The number 6 is found at position 3 (index 2). Three comparisons were needed.

Question CS7.17

A program allows the user to input a number between 1 and 10 (inclusive). Identify test data for each of the four test data types.

Answer: Normal: any number from 1 to 10 (e.g., 5). Abnormal: a value outside the range or wrong type (e.g., 0, 11, "abc", 3.5). Extreme: the boundary values that should be accepted (1 and 10). Boundary: values on both sides of each boundary (0 and 1 at the lower end, 10 and 11 at the upper end).

Question CS7.18

Write a pseudocode validation routine using a WHILE loop to input a number and check it is between 1 and 100 inclusive.

Answer:

`

Number ← INPUT("Enter a number between 1 and 100")

WHILE Number < 1 OR Number > 100 DO

OUTPUT("Invalid, please try again")

Number ← INPUT("Enter a number between 1 and 100")

ENDWHILE

OUTPUT("Valid")

`

Question CS7.19

A program stores a number for a user to guess. The user has up to 10 attempts. After each turn the program outputs whether their guess is smaller, larger, or equal. Identify the inputs, processes, and outputs.

Answer: Inputs: the stored number, the user's guess each turn. Processes: compare the guess to the stored number, count the number of attempts, check if the guess is correct or if 10 attempts have been used. Outputs: "too small", "too large", or "correct" after each guess, the number of attempts if correct, and the answer if all 10 guesses are used.

Question CS7.20

Identify which validation rule this algorithm uses: INPUT Num; IF Num > 0 AND Num < 100 THEN OUTPUT "Valid" ELSE OUTPUT "Invalid" ENDIF.

Answer: This algorithm uses a range check. It validates that the input number is within the range of greater than 0 and less than 100. Any value outside this range is rejected as invalid.

Key Formulas and Concepts

  1. Average = Total / Count
  2. Bubble sort maximum passes = Length of array − 1
  3. Linear search worst case comparisons = Length of array (item not found)
  4. Totalling pattern: Total ← 0, then Total ← Total + Value (inside loop)
  5. Counting pattern: Count ← 0, then Count ← Count + 1 (inside loop)
  6. Finding minimum: Initialise Minimum ← large value, then IF Number < Minimum THEN Minimum ← Number
  7. Finding maximum: Initialise Maximum ← small value, then IF Number > Maximum THEN Maximum ← Number
  8. Bubble sort swap pattern: Temp ← A, A ← B, B ← Temp (three-variable swap)
  9. SUBSTRING(String, StartPosition, NumberOfCharacters) — extracts part of a string for format checks
  10. Check digit verification: Calculate digit from data, compare with stored check digit

  2. Write pseudocode algorithms using correct constructs (IF/ELSE/ENDIF, WHILE/ENDWHILE, FOR/NEXT, INPUT, OUTPUT)
  3. Perform and show the working of a linear search step by step
  4. Perform and show the working of a bubble sort pass by pass, clearly showing each comparison and swap
  5. Identify and provide examples of all four types of test data (normal, abnormal, extreme, boundary) for a given scenario
  6. Complete trace tables accurately for algorithms with selection (IF) and iteration (WHILE, FOR) — record every variable change
  7. Identify and explain the six types of validation (range, length, type, presence, format, check digit)

  9. Find and correct errors in algorithms by comparing actual output to expected output using trace tables or code reading
